# 增量更新协议

## 输入

- 最近版 `resume_ir_vN.yaml`
- 最近版 `source_manifest_vN.json`
- 用户明确指定的当前工作区
- 可选：最新 JD

## 处理步骤

1. 建立当前 source manifest：相对路径、类型、修改时间、文件大小、内容摘要；不记录密钥内容。
2. 与上一版 manifest 比较，标记 `added`、`modified`、`deleted`、`unchanged`。
3. 只对 added/modified 文件提取新证据；读取可用 Git diff 时，将 diff 作为辅助证据，不能用提交次数推导影响。
4. 将证据映射到既有项目/经历。若时间、个人 ownership、数字或事实冲突，加入待确认项。
5. 仅更新被证据支持的 bullet，保留没有证据变化的内容。
6. 生成新版本，不覆盖旧版本。

## 变更报告格式

- 新增：新职责、新项目、新指标、新奖项、新技术且有来源。
- 修改：已有事实因新材料而更准确或更完整，注明旧→新和来源。
- 删除：原始材料被用户撤回或已确认失效；不得仅因扫描不到就删除。
- 待确认：来源不一致、OCR 不可靠、团队/个人归属不清、指标没有证据。
- 未采用：不相关、重复、低置信或敏感信息。

## 不变量

- 旧版本文件和旧 Resume IR 必须保留。
- 无新证据时不得重写、强化、扩张或量化既有表述。
- 不得自动更正日期、公司、职位或个人 ownership；必须由证据或用户确认支持。
